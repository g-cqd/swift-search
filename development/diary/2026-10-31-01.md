# 2026-10-31 (01) — enum-case labels, and an index with no record

Both defects came from a first run against a 2,982-file iOS app (the reference app).

`usages` of an enum case `invalid(from:action:)` listed five uses of another enum's case of the same name,
`invalid(from:calling:)`, beside the real ones. Enum cases had no signature, so the
label check that already separated function overloads never ran for them. A case now records its associated values as
parameters. Patterns may drop labels (`case .x(let a, let b)`, or `case .x(let all)`), so an unlabeled argument fits any
parameter of a case. As a result one such pattern in the other enum's own `switch` is still reported, marked `(by name)`.

`lsp callers` on an app's package returned nothing, with exit 1, while hover worked: sourcekit-lsp's index held no
units for it. The package declares only `.iOS(.v18)`, which looked like the cause, but it was not: a small iOS-only
package importing UIKit is indexed. The cause was a build-tool plugin that imports `XcodeProjectPlugin` without
`#if canImport`. SwiftPM cannot build it outside Xcode, so it stops at "build planning stopped due to build-tool plugin
failures". sourcekit-lsp's log shows the same failure as "Initial package loading", and then it indexes nothing.
`swiftPM.skipPlugins`, set in `.sourcekit-lsp/config.json`, does not change that in 6.4.2. The flag was tried and
dropped, because it would have been an option that does nothing.

So the fix is to say so. An empty answer to references, implementations, callers or callees now checks whether the
index knows the symbol at all (references including the declaration). When it does not, the answer carries a note,
printed on standard error by the CLI and returned as `notes` in JSON and MCP. The check costs one more request, and
only when the answer is empty. A test pins the plugin case, so a sourcekit-lsp that starts loading such packages shows
up as a failing expectation.

The fix for the package itself is on its side: wrap the import in `#if canImport(XcodeProjectPlugin)`.

Later the same day, the unlabelled patterns got narrower. A leading-dot member that is the whole pattern of a `switch`
case or an `if`/`guard`/`while case` records its subject's written type. For `self` that is the enclosing type; for a
parameter it is the last name of its declared type, with optionals unwrapped. The resolver treats that type as it treats
a written base. On the app, the `switch self` in the other enum's own `errorDescription` stopped counting as a use. Uses
whose subject's type the syntax does not give are still kept for every case of the name: patterns nested in another
(`.recording(.invalid(…))`) and `catch` clauses.
