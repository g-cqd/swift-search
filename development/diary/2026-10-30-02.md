# 2026-10-30 (02) — analyzerkit's head and AemiJSONRPC

The family's pins moved together first: AemiProtobuf (`fe7573c`), then analyzerkit (`6c8f556`), then this package, all
on aemi `5e56014`, AemiJSON `44aed49` and AemiRegex `637ffee`. The 63 tests passed on the new pins before any code
changed.

0006 replaced five pieces of this package with analyzerkit's: the line index for LSP columns, the toolchain's
sourcekit-lsp, the session's freshness memo (H3), `SourcePath.absolute` and `SearchOutcome`. 0007 moved both protocols
onto AemiJSONRPC. To show nothing else changed, the commit before each step was built in a worktree and both binaries ran
the same queries. Everything compared came out byte-equal: ten `find` and `usages` runs (with and without the index
store), an MCP session including a real sourcekit-lsp definition, and `lsp definition`. Two behaviours changed on
purpose and have tests. A request the client gives up on now tells sourcekit-lsp. An LSP offset inside a surrogate pair
now names its scalar instead of landing three bytes too far.

The MCP transport took about half the time on a megabyte of pings, with 2.6 times less CPU (debug builds). The load
average was between 250 and 300 all afternoon, which also kept `lsp references` from finishing: sourcekit-lsp never
finished its background index.

Two snags. Every family checkout's `.build` is a link into `~/Library/Caches/g-cqd-build`, and that directory had been
emptied, so SwiftPM failed with "The file “analyzerkit” couldn’t be saved in the folder “g-cqd”" until the link's target
was created again. Also, `run(reading:)` had to be `@concurrent`, because the library's `run` is concurrent and the
sequence's conformance could otherwise be isolated.
