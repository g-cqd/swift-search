# 2026-10-29 (01) — Extracting the search from SwiftStaticAnalysis

## What was extracted

SwiftStaticAnalysis `SymbolLookup` (5,456 lines) with the parts of `SwiftStaticAnalysisCore` it used: the declaration
and reference collectors, the models, the IndexStore reader, the parallel processor. Its CLI surface was `swa symbol`, its
MCP tool `search_symbols` (on the MCP Swift SDK), its LSP use a spike client (`[String: Any]`, a blocking byte-at-a-time
reader inside `async`).

Replaced, not copied:

| SwiftStaticAnalysis | swift-search |
| --- | --- |
| `SwiftFileFinder`, glob filters | analyzerkit `SourceDiscovery`, `PathFilter`, `SourcePath` |
| `ParallelProcessor`, no cache | analyzerkit `CorpusScanner` (bounded by Aemi's `mapConcurrently`, facts cache) |
| `IndexStoreReader`, `IndexStorePathFinder` | analyzerkit `IndexStoreSession`, `IndexStoreLocation`, `ToolchainResolution` |
| Swift `Regex` with a time budget and an antipattern filter | AemiRegex: linear time, no budget needed |
| scope tree walked per query | the container chain recorded on each declaration |
| USR decoding by heuristics for containers and `static` | `childOf` relations and symbol kinds from the index |
| MCP Swift SDK | a stdio server on AemiJSON |
| `SourceKitLSPClient` spike | `LanguageServerConnection` on swift-subprocess: framing decoder with limits, any number of requests in flight, deadlines, server requests answered |

## Probes

1. **Linking sourcekit-lsp.** A package on analyzerkit 651d1ac and sourcekit-lsp `swift-6.4.1-RELEASE`: `swift package
   resolve` fails, "indexstore-db is required using two different revision-based requirements". Without analyzerkit it
   resolves; swift-syntax `from: 604.0.0` against `release/6.4.x` resolves to the branch (same commit 050f1a3). ADR-0001.
2. **Index-store paths.** The first index test failed: matches came twice. The store records `/private/var/...` (the
   compiler's realpath); analyzerkit `SourcePath.canonical` spells the corpus `/var/...`. Index paths are now canonicalized
   before they are compared. Kept as `IndexStoreTests`.
3. **Simple names in the index.** The old resolver asked IndexStoreDB for the exact name, which for a function is
   `fetch(id:)`: a function was never found by `fetch`. Now a prefix query filtered on the base name.
4. **CRLF.** `"\r\n"` is one `Character`; splitting on `"\n"` kept CRLF lines whole and shifted every line number after
   the first. Found by `TextPositionsTests`; the context extractor had the same bug. Both split on all three line ends.
5. **sourcekit-lsp's index.** References, implementations, callers and workspace symbols came back empty on a fresh
   package: the background index was not built yet. `workspace/synchronize` with `index: true` (not experimental in 6.4.1)
   waits for it; every index-backed query sends it first. Then all six operations answered on the probe package, about
   0.4–1.8 s per command including the server's start.

6. **Dogfood.** `swift-search usages SourcePosition.location Sources Tests` by name listed 35 uses, all of other
   `location`s (`converter.location(for:)` among them); a property with a non-function type is no longer counted as
   called. With `--index-store` on the package's own build it listed none: the property was dead, and is removed.
